#### 2.1.1

- Same changes as 2.1.0, which was tagged but never reached npm: the publish workflow ran on `lts/*` (now Node 26), where `npm ci` cannot install `isolated-vm`. CI is now pinned to Node 24.

#### 2.1.0

Fixes

- Show Canolite's real error instead of n8n's generic "Your request is invalid or could not be processed by the service". A failed synchronous render now reads e.g. `Render failed: Remote image returned HTTP 403`, with the render UID, warnings and a fix hint. 400 validation errors list each bad field; 401/404/413/429/5xx and non-JSON (wrong Base URL / proxy error page) responses each get a specific message.
- Video Frame Rate and Quality no longer always send `30` / `balanced`, which overrode the template's and project's own video settings. They now default to **Template Default**.
- Image Scale allows 4x, matching the API.
- A trailing slash in the Base URL no longer produces `//v1/...` requests; whitespace around a pasted API key is trimmed.
- Render UIDs are trimmed and URL-encoded in Get Status.
- Polling (video Synchronous Request) survives brief network or 5xx errors instead of failing on the first one.

Features

- **Template** resource: **Get Many** (Return All / Limit, search, video-only filter) and **Get** (with editable `fields`).
- Video **Scale** option.
- **Wait for Completion** for Batch (one output item per finished job) and Get Status, with **Max Wait Time**, **Poll Interval** and **Fail If Any Job Fails**.
- **Download File**: put the finished image or video in binary data for the next node. The API key is only sent to the Canolite Base URL's own origin (needed for `MEDIA_ACCESS=private`).
- **Fail on Warnings**: treat Canolite warnings (unknown field, refused `image_url`) as errors.
