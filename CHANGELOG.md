#### 2.1.2 — 2026-11-19

The first 2.1 release on npm. 2.1.0 and 2.1.1 were tagged on GitHub but never
published (the publish workflow could not install dependencies on Node 26); all
of their changes are included here. No breaking changes: existing 2.x workflows
keep working.

**Error handling**

- Failed requests now show Canolite's own error instead of n8n's generic *"Your request is invalid or could not be processed by the service"*. A failed synchronous render reads e.g. `Render failed: Remote image returned HTTP 403`, with the render UID, any warnings and a hint on how to fix it.
- Each kind of failure gets its own message: invalid fields (each one listed), wrong or revoked API key, template or render not found, request too large, server busy (with Retry-After), server error, and a wrong Base URL or proxy error page.
- The template picker, the **Fields** form and the batch field dropdown use the same messages, e.g. `Canolite rejected the API key`, `Could not load template "tmpl_x": Template not found` or `Could not reach Canolite at …`, instead of "Request failed with status code 401".
- While waiting for a render, a brief network or 5xx error is retried; the node gives up only after three failures in a row.

**New**

- **Template** resource: **Get Many** (Return All / Limit, search, *Video Templates Only* filter) and **Get** (with the template's editable `fields`).
- **Wait for Completion** for **Batch** (one output item per finished job) and **Get Status**, with **Max Wait Time**, **Poll Interval** and **Fail If Any Job Fails**. A failed job is returned with `status: "failed"` and its `error` instead of failing the whole batch.
- **Download File**: puts the finished image or MP4 in binary data (property **Binary Property**, default `data`) for the next node. The API key is only sent to the Canolite Base URL's own origin, which also makes downloads work with Canolite's `MEDIA_ACCESS=private`.
- **Fail on Warnings**: treat Canolite warnings (unknown field name, refused `image_url`) as errors.
- Video **Scale** option.

**Fixed**

- Video **Frame Rate** and **Quality** were always sent as `30` / `balanced`, overriding the template's and project's own video settings. They now default to **Template Default**.
- **Scale** goes up to 4x, matching the Canolite API (it stopped at 3).
- A trailing slash in the Base URL no longer produces `//v1/…` requests, and spaces around a pasted API key are removed.
- **Get Status** trims and URL-encodes the render UID.

**Other**

- The publish workflow runs on Node 24 (on Node 26, `npm ci` cannot install `isolated-vm`).
- Tested in n8n 2.48 against Canolite 1.12.2: image, video, batch, Get Status, Template, file download and every error case. Canolite 1.12.2 or later is recommended — 1.12.0 and 1.12.1 cannot render inside Docker / Coolify.
